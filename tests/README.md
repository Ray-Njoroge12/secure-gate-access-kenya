# Visitor Management System - Comprehensive Testing Suite

This testing suite provides rigorous automated testing for your visitor management system to ensure high integrity and functionality across all platforms (Resident, Security, and Visitor).

## Overview

The testing suite validates:
- **Resident Platform**: Authentication, invitation creation, data management
- **Visitor Platform**: Registration flow, consent handling, access code generation
- **Security Platform**: QR code/PIN verification, audit logging
- **Data Security**: Encryption/decryption, privacy compliance, data retention
- **Performance**: Load testing, concurrent operations
- **Edge Cases**: Error handling, malformed inputs, expired tokens

## Test Files

### `system-integrity-tests.ts`
The main test file containing comprehensive test suites for all system components:

- **🏠 Resident Platform Tests** (6 tests)
  - Authentication and session management
  - Single-use and multi-use invitation creation
  - Rate limiting enforcement
  - Data retrieval with proper filtering

- **👤 Visitor Platform Tests** (4 tests)
  - Registration with valid invitation tokens
  - Invalid token rejection
  - Consent requirement enforcement
  - Access code generation verification

- **🛡️ Security Platform Tests** (6 tests)
  - QR code verification and single-use enforcement
  - PIN verification system
  - Audit trail logging
  - Access attempt tracking

- **🔒 Data Security & Privacy Tests** (4 tests)
  - PII encryption/decryption validation
  - Data retention policy enforcement
  - GDPR consent compliance
  - Privacy law adherence

- **⚡ Performance & Load Tests** (2 tests)
  - Concurrent invitation creation handling
  - Bulk visitor registration efficiency

- **🔍 Edge Cases & Error Handling** (3 tests)
  - Expired invitation token handling
  - Malformed QR code/input handling
  - Database connection failure graceful handling

### `run-system-tests.ts`
Automated test runner that:
- Checks system prerequisites
- Executes all tests
- Generates comprehensive reports
- Provides system integrity assessment
- Offers actionable recommendations

## Prerequisites

### Environment Setup
1. **Environment Variables**: Ensure your `.env` file contains:
   ```env
   VITE_SUPABASE_URL=your_supabase_url
   VITE_SUPABASE_ANON_KEY=your_anon_key
   SUPABASE_SERVICE_ROLE_KEY=your_service_role_key
   ```

2. **Database**: Supabase instance must be running and accessible

3. **Dependencies**: All required packages installed:
   ```bash
   npm install
   ```

## Running Tests

### Quick Test Run
```bash
# Run all system integrity tests
npm run test:system

# Or run specific test file
npm run test tests/system-integrity-tests.ts
```

### Comprehensive Test with Report

## Test Data Management

### Automatic Cleanup
- Tests create temporary data for validation
- All test data is automatically cleaned up after execution
- No impact on production data

### Test Isolation
- Each test runs in isolation
- No dependencies between tests
- Parallel execution safe

## Security Considerations

### Test Environment
- Tests use service role key for admin operations
- Ensure test environment is separate from production
- Test data includes encrypted PII for validation

### Data Privacy
- All test visitor data is fake (generated by Faker.js)
- Real PII is never used in tests
- GDPR compliance is validated, not violated

## Troubleshooting

### Common Issues

**Environment Variables Missing**
```bash
Error: Required dependency missing: @supabase/supabase-js
```
Solution: Ensure all environment variables are set in `.env`

**Database Connection Failed**
```bash
Error: connect ECONNREFUSED
```
Solution: Verify Supabase instance is running and accessible

**Permission Denied**
```bash
Error: insufficient_privilege
```
Solution: Check service role key has proper permissions

**Rate Limiting**
```bash
Error: Too many requests
```
Solution: This is expected behavior - tests validate rate limiting works

Run tests with verbose output:

```bash
npm run test -- --reporter=verbose tests/system-integrity-tests.ts
```

## Extending Tests

### Adding New Test Cases

2. Follow existing patterns for setup/cleanup
3. Use proper assertions and error handling
4. Update this documentation

### Custom Test Scenarios
```typescript
it('should handle custom scenario', async () => {
  // Setup test data
  const testData = await setupCustomScenario();
  
  // Execute test
  const result = await executeCustomTest(testData);
  
  // Validate results
  expect(result).toBeDefined();
  expect(result.status).toBe('success');
  
  // Cleanup if needed
  await cleanupCustomScenario(testData);
});
```

## Continuous Integration

### GitHub Actions Example
```yaml
name: System Integrity Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-node@v2
      - run: npm install
      - run: npm run test:system
        env:
          VITE_SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          VITE_SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
          SUPABASE_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_SERVICE_KEY }}
```
